## 一、怎么写才"识别度高"（六要素 + 判别要点）

每条描述必须能回答下面 6 个问题，缺一项就会掉识别率：

1. **用手**：单手（左/右/任一）或双手（同时/先后、主手与辅手的关系）。左右手**不作为判别特征**（要能换手识别），只作记录。
2. **指式**：拇/食/中/无名/小 各自「伸直 · 半弯 · 全弯」；是否 拇指食指相扣成环；是 五指并拢平掌 还是 握拳。
3. **掌向**：掌心 朝上 / 朝下 / 朝内（对自己）/ 朝外（对镜头）/ 朝向身体中线。"手背朝上" 一律等价写成 "掌心朝下"。
4. **位置**：手中心的身体锚点 = 「肩 / 胸 / 腹 / 鼻 / 耳 / 下颌 / 头顶」+「肩连线以上 / 以下」+「中线 / 偏左 / 偏右」。**写到这一层就够了，不需要量化成"几肩宽"** —— 判据全部用比值实现，位置差半拳、角度差十几度都能命中。
5. **运动**：方向（上/下/左/右/朝镜头/离镜头）+ 路径（直线/弧线/圆圈/往复）+ **次数** + 幅度（小 <0.1 肩宽 / 中 0.1–0.4 / 大 >0.4）+ 速度（慢/匀/快）。
6. **结束姿态**：停在哪里、是否收回、是否静止保持（静止词也要写"保持 N 秒"）。

另外每条必须写 **判别要点**：最容易和它混的词是哪个，看哪个特征能一刀切开，尽量给可量化阈值（正负号、比值、次数、距离）。

**书写约定**

- 坐标与骨骼 JSON 一致：`x` 向右、`y` 向下、`z` **负值更靠近镜头**（见 `dataset/video/*.json` 里的 `coordSpec`）。
- 深度方向统一写「朝镜头 / 离镜头」，不要写"向前"（既可能指身体前方也可能指镜头，有歧义）。
- 分段动作用（一）（二），并在判别要点里给出**分段边界**（秒数或占总时长百分比）。
- 引用实测数值时标注样本名（如 `s01_001`），重录后按新样本更新。
- 实测符号说明：`指伸比` = 指尖到手腕的距离 ÷ 掌长（掌长 = 腕到中指根），伸直 ≈1.5–2.1、弯曲 ≤1.0；`ny` = 手掌平面法线的 y 分量，**ny<0 → 掌心朝上，ny>0 → 掌心朝下/手背朝上**（本批样本均为同一只手起手，换手动判别时以掌向语义为准）；`dz` = 食指尖 z − 腕 z，**dz<0 → 指尖朝镜头，dz>0 → 指尖离镜头**。

### 识别协议（比描述更决定"出不出图"）

系统有**两条识别通道**，`描述文字本身不参与识别`：

- **静态判据通道（001-010 已启用）**：不看运动轨迹，只看"手停住时长什么样、停在身体哪个位置"。
  同一个词连续命中 `STATIC_HOLD_MS 450ms`、且掌心在 400ms 窗口内漂移 ≤0.25 肩宽 → 出图。
  实测"动作到位 → 出图"约 **0.5 秒**，即 §三 写的"停住 0.5-1 秒"。判据与阈值见 §2.1（单手）与 §2.4（双手）。
  两只手同时检出时**先跑双手判据**（§2.4），命中即出该词、不再看单手；没命中才回落到单手判据。
- **轨迹 DTW 通道（011 起）**：按运动能量切段，与模板做 DTW 匹配。
  001-010 的 DTW 命中一律**否决**（否则 004 天气第一段转圈就会抢跑出图，第二段又出一张）。
  ⚠ 被否决的 DTW 命中**不会**占用重复触发锁（`lastTriggerAt` 会回滚）—— 否则一次没出图的 DTW 命中
  会把紧随其后 700ms 内的静态判据饿死（实测 0.55–0.7× 远距下 008 了 连续命中 797ms 却整段不出图）。

录制 / 表演协议（两条通道都适用）：

1. **到位后停住 ≥0.5 秒**（推荐 1 秒）：静态判据需要 450ms 连续命中 + 约 0.2s 特征平滑。
   抬手/放下过程中的串词实测最长只有 104ms，全部被这道门滤掉。
2. **一条录制 = 一个动作**：DTW 通道按运动能量切段，同一次录制里的大幅动作会抬高能量阈值、盖掉小幅动作。
3. **打完别立刻把手甩出画面**：收尾时手在画面里再停一下；建集会丢弃"收尾时手已离场"的段。
4. **不需要卡精确位置/角度**：所有特征都是比值（除以掌长、除以肩宽、y 轴乘宽高比），
   与人离镜头远近、分辨率、宽高比无关。**描述里的实测数值是记录锚点，不是判据。**
5. **身体骨骼必须开**：位置特征以「双肩中点为中心、肩宽为尺度」，004 还要用鼻尖做锚点。
   关掉身体骨骼 → 静态判据整条不工作（页面右下角 HUD 会提示"没拿到「手 + 肩」"）。
6. **每词 ≥3 条**：换速度/幅度/手各录一条。单条录制时原型全来自同一次表演，换人换手会掉。
7. **不出图先看 HUD**：识别页右下角实时显示「命中/最接近哪个词 + 差哪一维 + 全部特征值」，按 `D` 键隐藏；
   同样内容会 POST 到 `/diag`，落盘在 `/tmp/sign_diag.log`（`ev=static-feat / static-hit / static-trigger`）。

**特征含义**（全是比值，与镜头远近/分辨率/宽高比无关）

- `ext0` `ext1` `ext2`：拇指 / 食指 / 中指的「指尖-指根直线距离 ÷ 三节指骨弧长」，伸直 ≈1.0、弯曲 ≈0.3。
  `ext2` 是 006 吃（中指伸直 0.99-1.00）与 007 米饭（中指弯曲 0.46-0.58）的主分界，阈值 0.85 / 0.75。
- `mx3` `mn4`：中/无名/小指 `ext` 的最大值、食/中/无名/小指 `ext` 的最小值。`mn4` 高 = 四指全伸的平掌（003）；
  `mx3` 低 = 只有食指伸直。002 用 `mx3≤0.85` 挡掉 009 认识（食中指一起伸，实测 0.92-0.96）。
  `mn4` 还用来分开 008 了（五指全伸 0.99-1.00，`mn4≥0.88`）与 010 很（只伸食指 0.47-0.52，`mn4≤0.70`）。
- `dziR`：(食指尖 z − 食指根 z) ÷ 掌长。**负 = 指尖比指根更靠近镜头（指向对方）；正 = 指尖离镜头（指向自己）**。

  ⚠ **它只对"指镜头 / 指自己"这一对有效**：手指**横着**指的时候（009 认识 指尖左右相对、010 很 食指横伸）
  x 才是主分量，`dziR` 会被 z 噪声带出 −0.4…−0.9 的假值，看着像"指向镜头"。判横指要看 x 分量占比：
  002 你 `dx` 只有 +0.08…+0.34、`dz` −0.91…−1.00（真指镜头）；009 认识 `dx` +0.72…+0.89（横指、朝另一只手）。
- `ny`：掌平面法线的 y 分量，`|ny|` 大 = 掌面接近水平。
  ⚠ **符号不可靠**：现场遥测里同一个「今天」既有 `ny=−0.79` 也有 `ny=+0.91`（MediaPipe 会随手的翻转、
  左右手判定翻号），所以 003 只判 `|ny|`；002 的 `ny≥−0.25` 是「指背大致朝上」的宽松版，不是严格符号判据。
- `spr`：相邻指尖间距（食↔中、中↔无名、无名↔小）的平均值 ÷ 掌长。小 = 五指**并拢**（003 录制 0.24-0.31、现场 0.27-0.41），
  大 = 五指**张开**（008 了 保持段 0.46-0.49）→ `spr≤0.42`（003）与 `spr≥0.44`（008）互为反面，**都别再放宽**。
  ⚠ 光靠 `spr` 不够：008 了 的**抬手期**（0.75-1.36s）五指还没张开，`spr` 只有 0.23-0.36，会连续命中 003 今天 达 492ms
  而误出图。所以 003 又加了 `thAt5≤0.65`、008 又加了 `dy1≥0.60`（见下）两道独立保险。
- `tiR` `tmR`：拇指尖↔食指尖、拇指尖↔中指尖的距离 ÷ 掌长。两者都小 = 三指相扣成"Q"（004）。
  `tmR` 还单独用来分开 001 我（拇指自然内收，0.17-0.51）与 008 了（拇指外张，0.84-1.12），阈值 `tmR≤0.70`。
  `tiR≤0.55` = 007 米饭 的"拇食微张"（0.14-0.46），`tmR≥0.45/0.50` 把 004 天气（0.12-0.31）挡在 006/007 之外。
- `nd`：掌心↔鼻尖距离 ÷ 肩宽。小 = 手凑到脸前（004），大 = 手在胸腹前（001/003/005）。
- `hy`：掌心相对**双肩连线中点**的高度 ÷ 肩宽（y 已乘宽高比）。**正 = 肩连线以上，负 = 肩连线以下。**
- `thUp`：(拇指根 y − 拇指尖 y) × 宽高比 ÷ 肩宽，正 = 拇指朝上。
- `mdI` `mdM` `mdT`：食指尖 / 中指尖 / 拇指尖 ↔ **嘴角中点**（pose 9、10 的中点）的 2D 距离 ÷ 肩宽。
  小 = 手凑到嘴边（006 吃 0.04-0.32、007 米饭 0.05-0.26），大 = 手在胸腹前（其它词都 ≥0.59）→ 阈值 0.35/0.40。
  这是 006/007 的**位置身份证**，比 `hy`/`nd` 准得多（`nd` 只到鼻尖，分不清"嘴边"和"下巴前"）。
- `eyeH`：掌心相对**双眼连线中点**（pose 2、5）的高度 ÷ 肩宽，负 = 手在眼以下。
  与 `hy` 一起把"嘴部高度"框成一条带：`hy≥−0.30` 且 `eyeH≤−0.15`（006）/`eyeH≤−0.10`（007）。
- `thAt5`：拇指尖 ↔ 食指根 的 **2D** 距离 ÷ 掌长。小 = 拇指内收或压在食指根上，大 = 拇指外展。
  010 很 0.06-0.17（`≤0.28`，"拇指尖按食指根"）、003 今天 0.17-0.55（`≤0.65`）、008 了 0.59-0.91、002 你 1.01-1.34。
  ⚠ **只能用 2D**：MediaPipe 手部的 z 精度远低于 x/y，同一帧用 3D 量会把 010 很 放大到 0.25-0.43，看着像"没按住"。
